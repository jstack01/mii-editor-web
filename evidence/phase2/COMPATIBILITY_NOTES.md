# Phase 2 source characterization (recorded before implementation)

Authoritative files: `EXTRACTED-SWF/classicGUI.swf/scripts/mii/MiiCharacterData.as`, `values/MiiDataValue.as`, `values/Range.as`, and renderer frame conversion methods. The corresponding assets module model is identical.

- Numeric initialization extracts bits without clamping; writes perform AS3 `int` coercion then clamp. Preserve reserved bits on writes, including raw invalid data around the edited field.
- Raw binary loads require 74 bytes. Invalid binary loads return false without replacing existing blocks. Strict `fromBytes`/`fromHex` are internal APIs and continue to reject invalid fixtures.
- Legacy `setHexData` matches alphanumeric pairs, skips separators, accepts partial parseInt prefixes/non-hex letters, pads to 74 bytes and truncates excess. Empty string is a no-op; nonempty strings with no matching pairs load zero bytes. AS3 global String.match returns an empty array for no matches (AIR SDK String reference), unlike JavaScript null; adapt deliberately.
- ID fields each contain four bytes. Insufficient tokens leave the ID unchanged. `getHex` pads only decimal values below 10; bytes 10 through 15 appear as a–f. Preserve this formatting bug (hyphen separators still allow correct ID re-import); provide strict/raw canonical binary serialization separately.
- Names occupy ten UTF-16 code units each. Read skips all zero units; writes zero pad and may split surrogate pairs.
- XML field order is `valueNames`, not declaration order. XML vertical Y values are reversed; eyebrow limits shift by three; mingles is inverted; five type values map through feature permutations. Import uses only the first direct mii child, resets all words, ignores mii/@value and unknown fields, and processes repeated data fields in order. Missing name/creator child access can fail after resetting/partially writing; the string wrapper catches errors. These are observable partial-state effects, not a transactional import.
- XML round trip cannot promise reserved-bit preservation: XML import resets unspecified bits. Raw binary/hex round trips remain exact. Packed raw values above declared bounds can also be clamped by XML import.
- XML parser uses the browser native DOMParser, with an explicit AS3/E4X adapter. Import behavior for original-produced XML is required; unverified exotic E4X/namespace/DTD constructs must not be advertised as identical. External DTD/style references in original export are inert metadata, never fetched.
- Randomization follows the exact 45-name order then ID bytes high-to-low (49 draws), changes names to Random/Mii Editor, preserves Wii ID/reserved bits, and selects inclusive uniform integer ranges. Inject an RNG for reproducible tests; default is Math.random.

Language reference links: https://airsdk.dev/reference/actionscript/3.0/String.html and https://airsdk.dev/reference/actionscript/3.0/XML.html . Runtime edge cases are source/language-derived, not certified against an executed Flash VM.

Browser XML boundaries: native DOMParser is required for XML import; numeric/binary/hex and XML string export remain usable without a DOM. Internal DTD subsets and complex element-valued name/creator fields are explicitly rejected as unverified constructs, not silently approximated. The original exported external DTD and stylesheet references are retained and not fetched. Native XML declaration/formatting differences are not byte-for-byte E4X serialization claims; document semantics, data order and values are tested. AS3 default XML.ignoreWhitespace trims parsed text nodes, which can remove leading/trailing spaces on XML round trips even though binary preserves them.

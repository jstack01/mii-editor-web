# Manual publishing process for Codex / repository owner

No Actions workflow or automatic release publishing is configured. Ordinary development commits are local until explicitly pushed. Publication requires an explicit request and owner approval of the reviewed source, archive and unresolved licensing/provenance concerns.

1. Review `LICENSE.md` and `NOTICES.md`. New code is currently unlicensed; generated graphics have unresolved redistribution rights. Owner approval is not third-party permission. Do not silently add an MIT license or assume that archival hosting grants rights.
2. Use the existing repository/history. Keep SOURCE/, EXTRACTED-SWF/, old recovery evidence/tools and source-comparison tests locally ignored/untracked. Do not delete them or rewrite history. Check `git ls-files`, not just what Finder shows. The public build uses committed generated resources.
3. In web/, run `pnpm install --frozen-lockfile`, `pnpm typecheck`, `pnpm test`, `pnpm build`, `pnpm test:browser` and `pnpm test:browser:production`. On the original development machine also run `pnpm test:legacy` and the local Python source-integrity tests. Record missing browser/device environments honestly. If generated resources intentionally change, explicitly recover/review/update their hash inventory first.
4. Update the application version, README download version, release notes and migration status. Commit the reviewed public source locally. No originals, credentials, node_modules, evidence or prebuilt artifacts belong in its current Git tree. Test a clean source snapshot/clone without private folders.
5. From the project root run `python3 scripts/package-release.py --version v0.1.0-preview.2` (substitute the next approved version). It packages the prebuilt dist and startup/docs/notices using an allowlist, creates four `release/mii-editor-web-{macos,linux,windows,static}-VERSION.zip` files, individual checksums/manifests, `SHA256SUMS-VERSION.txt` and `release-set-VERSION.json`. Build metadata pins the current clean commit. `--allow-dirty` is local-testing-only; such a package cannot be published by the publisher.
6. Run `node web/scripts/distribution-browser.mjs --archive release/mii-editor-web-EDITION-VERSION.zip` for **each of the four editions**. It extracts and checks the actual archive, verifies root/nested/share/import/export operations using plain local servers and Apache where available, and writes a sibling `.verification.json` for that exact ZIP hash; the macOS case uses the real default port 8080 and restarts the server to check persistence. Preserve internal verification reports locally. Remaining platform/hardware checks are not magically complete.
7. Show the owner: repository, reviewed commit, public/current source paths, excluded local materials, ZIP manifest/checksum, version and unresolved licensing concerns. **Wait for approval before this version’s public push or release. D1 approval does not authorize D2 publication.** Authentication through `gh auth login --web --secure-storage` is allowed before approval, but never print tokens or request a password.
8. After explicit approval only, run `python3 scripts/publish-release.py --repo jstack01/mii-editor-web --version VERSION --expected-commit FULL_REVIEWED_HASH --approve-public-upload`. This checks the clean reviewed commit/archive/verification, creates the public repository if absent, applies supported GitHub settings and verifies them, adds the matching origin if absent, pushes without force, creates a new annotated tag and publishes a prerelease with all four ZIPs and the combined checksum file. It never accepts a dirty snapshot, overwrites an unrelated origin or replaces an existing tag.
9. Verify the remote current tree excludes originals, repository settings show `has_issues=false`, **`has_pull_requests=false`**, `has_discussions=false`, `has_wiki=false`, and public forking is enabled. Do not substitute disabled merge buttons, interaction limits or an auto-close workflow for actually disabling pull requests. Download the published asset to a temporary directory and verify its SHA-256. Inspect GitHub's automatic source archive too: it is the tagged clean source, not the ready-to-run ZIP. Supply repository, Releases and direct ZIP URLs to the owner.

GitHub's supported PR feature control is documented at https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/enabling-features-for-your-repository/disabling-pull-requests and its REST repository field at https://docs.github.com/en/rest/repos/repos. Actual server-side settings cannot be verified until a repository exists; a request/config file is not proof. Publishing must abort before the source push if the API cannot confirm the requested values.

For future versions, the short process is: **build/test → update/review source → commit → package → verify extracted ZIP → obtain explicit release approval → publish**. Do not automatically publish every development change. Old history can contain Flash files because the owner explicitly accepted that; current HEAD, new tags/source snapshots and distributions must not.

Public repositories are inherently forkable. GitHub rejects changing `allow_forking` on public/personal repositories, so the helper omits it from mutation requests and still verifies that the returned value is true. This was confirmed during the initial publication and has a regression test. The reviewed v0.1.0-preview.1 application ZIP/tag remains unchanged; use the current main-branch publishing helper for later releases.

## D2 platform claims and package checks

Run `python3 -m unittest discover -s scripts -p 'test_*.py' -v` for server security/lifecycle, interpreter discovery and packaging guards. macOS supports the POSIX lifecycle tests; do not run platform-specific tests on another OS and call it Windows/Linux verification. Record real double-click, terminal, browser and close behavior separately. Windows and Linux ZIPs must remain clearly labeled as unverified on those operating systems until tested there. Do not silently remove those limitations from release notes.

The local ZIPs contain only their platform launcher/helper, Python server, compiled website, guide and notices. The static ZIP contains the website at its root plus guides/notices and no server scripts. Confirm all four contain identical compiled site bytes, no private/original/diagnostic/development materials, valid inventories and clean commit metadata. The publisher checks each archive’s exact verification hash and refuses any existing tag. It never replaces preview.1. Verify native ZIP executable permissions and quarantine behavior on each OS where available.

For local testing only, `--allow-dirty` creates clearly marked non-publishable artifacts. After the final local commit, package again without that flag and rerun all four extracted-package checks. The combined checksum is the downloadable verification file. Keep verification reports/manifests local rather than uploading unnecessary evidence.
